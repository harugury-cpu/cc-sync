# Automation Change Safety

업무 자동화 수정 전 안전장치와 검증 기준을 고정한다. “고치면 무엇이 깨질 수 있는지”를 먼저 보이게 만들고, 운영 데이터와 원본 디자인 파일을 보호한다.

## 반드시 먼저 할 것

- `task-gate`의 완료조건/실패케이스/검증방법을 자동화 맥락으로 구체화한다.
- 운영 데이터, Drive 파일, Illustrator 원본, 템플릿에 쓰는 작업이면 백업 또는 테스트 사본 가능성을 먼저 확인한다.
- 확실하지 않은 상태에서 “고쳤다”고 말하지 않는다.
- 수정 후에는 `automation-regression-check`로 검증 항목을 만든다.

## 완료조건 템플릿

```markdown
## 완료조건
- 문제 케이스가 재현되고 수정된다.
- 기존 정상 케이스가 계속 동작한다.
- 운영 데이터/파일/디자인 산출물에 중복·누락·덮어쓰기가 생기지 않는다.
- 실패 시 로그 또는 확인 가능한 흔적이 남는다.
- 수동 재실행해도 같은 결과물이 중복 생성되지 않는다.
```

## 실패케이스 템플릿

```markdown
## 실패케이스
- 시트/문서/보드/파일/레이어/템플릿 구조 변경으로 다른 자동화가 깨짐
- 날짜/시간대 오류로 잘못된 기간에 기록됨
- 트리거 또는 버튼 중복 실행으로 같은 항목/파일/아트워크가 두 번 생성됨
- 권한 부족 또는 API 토큰 문제로 조용히 실패함
- 일부 단계만 성공해 데이터나 파일이 반쯤 반영됨
- 테스트 사본이 아니라 운영 데이터/원본 파일에 잘못 적용됨
```

## 검증방법 템플릿

```markdown
## 검증방법
- 테스트 입력 또는 테스트 파일 1건 실행
- 정상 케이스 1건 실행
- 빈 값/예외 케이스 1건 실행
- 중복 실행 방지 확인
- 로그 확인
- 실제 운영 대상 반영 전 마지막 대상 확인
```

## 롤백/복구 질문

- 수정 전 원본 코드와 원본 파일을 복사해둘 수 있는가?
- 영향을 받는 시트/보드/폴더/디자인 파일을 백업할 수 있는가?
- 잘못 생성된 행/아이템/파일/아트워크를 식별할 기준이 있는가?
- 실패 시 수동으로 되돌릴 수 있는 범위인가?
