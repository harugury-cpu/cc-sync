# Automation Regression Check

업무 자동화 수정 후 “진짜 안전한지” 확인하는 체크리스트를 만든다. 테스트 코드가 없어도 운영자가 확인할 수 있는 수동 검증 절차로 바꾼다.

## 검증 원칙

- 완료를 주장하기 전에 검증 결과를 먼저 확보한다.
- 테스트가 없으면 수동 검증을 명시한다.
- 운영 데이터, 원본 파일, 디자인 산출물에 영향이 있으면 테스트 사본 또는 안전한 샘플로 먼저 확인한다.
- 정상 케이스와 문제 케이스를 둘 다 본다.
- 중복 실행, 누락, 덮어쓰기, 권한 오류를 반드시 확인한다.

## 기본 체크리스트

```markdown
## 자동화 수정 후 검증 체크리스트

### 1. 대상 확인
- 수정한 스크립트/서비스:
- 관련 함수/화면/버튼:
- 관련 트리거:
- 관련 시트/문서/보드/폴더/디자인 파일:

### 2. 문제 케이스
- 기존 문제가 재현됐는가:
- 수정 후 해결됐는가:
- 증거:

### 3. 기존 정상 케이스
- 정상 입력/파일 1건:
- 빈 값/예외 입력 1건:
- 권한/API 호출:
- 날짜/시간대:
- 템플릿/레이어/컬럼 구조:

### 4. 중복/누락/덮어쓰기 확인
- 같은 입력을 다시 실행했을 때 중복 생성되는가:
- 일부만 저장되는 경우가 있는가:
- 원본 파일이나 운영 데이터가 의도치 않게 덮어써졌는가:
- 실패 로그가 남는가:

### 5. 운영 반영 판단
- 운영 반영 가능 여부:
- 남은 위험:
- 사용자/팀에 알려야 할 내용:
```

## 출력 형식

```markdown
## 결론

- 실패:
- 미확인:

## 남은 위험
```
