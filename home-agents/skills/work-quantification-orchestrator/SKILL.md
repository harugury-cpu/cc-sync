# 업무정량화 구현 오케스트레이터

이 스킬은 tofu-at의 “리소스 스캔 → 작업 분해 → 역할 분리 → 검증 게이트” 방식을 Codex용으로 단순화한 업무정량화 전용 워크플로우다.

## 사용 시점

사용자가 다음을 요청하면 이 스킬을 사용한다.

- 업무정량화 프로젝트 구현 작업 사양서 작성
- PRD를 Apps Script 구현 단위로 분해
- Google Sheet 탭 구조와 Apps Script 책임 설계
- Monday 완료 이벤트 웹훅/동기화 설계
- 설문 HTML, 티셔츠/횟수/RC 계산 로직 설계
- 재설문, 미응답, 확인필요, 지원파트 시간 처리 설계
- 구현 전 테스트 케이스/QA Gate 작성

## 원칙

1. 먼저 기술 문제로 재정의한다.
2. 구현 전에 구조와 책임 분리를 확정한다.
3. 설명보다 모듈, 데이터 흐름, 함수 책임, 파일 구조를 우선한다.
4. Apps Script는 한 파일에 몰지 않고 서비스/저장소/계산/HTML 책임으로 나눈다.
5. 계산 기준은 코드에 숨기지 않고 Google Sheet 룰 탭에서 읽는다.
6. 완료건 이력, 업무 현재상태, 설문응답 이력, 계산결과를 분리한다.
7. 재설문은 새 업무 생성이 아니라 기존 업무 최신값 갱신이다.
8. 파트장/지원파트 시간은 설문 응답에 섞지 않고 별도 로그로 저장 후 item 기준 합산한다.

## 표준 진행 순서

### 1. 리소스 스캔

먼저 프로젝트 폴더를 확인한다.

- PRD
- 시트 구조 문서
- Apps Script `.gs`
- 설문 HTML
- Mermaid / draw.io
- 테스트 케이스
- 배포/인증 관련 파일

가능하면 `scripts/scan_project.py`를 실행해 현재 파일 구성을 요약한다.

### 2. 시스템을 모듈로 분해

기본 모듈은 아래를 기준으로 한다.

1. Monday 완료 이벤트 수집
2. 완료이벤트누적 저장
3. 업무로그 매칭
4. 설문 배치 생성
5. 설문 HTML 렌더링
6. 설문 응답 저장
7. 계산 엔진
8. 재설문/관리자 처리
9. 파트장/지원파트 시간 처리
10. 리포트 입력 데이터 생성
11. 테스트/검증

### 3. 데이터 흐름 확정

기본 흐름:

```text
Monday 완료 처리
→ 완료 보드 item 생성
→ 완료이벤트누적 append
→ 원래 업무 item ID + 담당자로 업무로그 조회
→ 같은 업무면 업무로그 최신값 갱신 / 아니면 신규 업무로그 생성
→ 라인업코드 기준 설문 배치 생성
→ 설문 HTML 응답
→ 설문응답원본 append
→ 업무로그 최신응답 갱신
→ 계산결과 재생성
→ AI HTML 리포트 입력값 제공
```

### 4. 구현 사양서 생성

작업 사양서는 `templates/IMPLEMENTATION_SPEC.md`를 기준으로 작성한다.
각 모듈은 `templates/MODULE_SPEC.md` 구조를 따른다.

### 5. 테스트 케이스 작성

테스트는 구현 전 작성한다. 기본 케이스:

- 라인업코드 있는 item 여러 개가 10분 안에 들어옴
- 라인업코드 없는 item이 들어옴
- 같은 원래 업무 item이 RC로 다시 완료됨
- 재설문 버튼으로 다시 응답함
- 미응답 상태가 남음
- 티셔츠 기본값보다 높게 선택되어 사유가 저장됨
- RC 선택 시 크로스체크/인계가 자동가산됨
- 파트장/지원파트 시간이 item에 별도 합산됨

### 6. QA Gate

구현 전/후에 `templates/QA_GATE.md`를 사용한다.
특히 아래는 반드시 검증한다.

- 같은 업무가 중복 계산되지 않는가
- 완료건 이력과 업무로그 현재상태가 섞이지 않는가
- 재설문이 새 업무가 아니라 기존 업무를 갱신하는가
- 라인업 묶음 설문 결과가 개별 item에 반영되는가
- 지원파트 시간이 원 담당자 개인 평가에 섞이지 않는가
- 계산결과가 룰 탭 변경에 따라 재생성 가능한가

## Codex sub-agent 사용 기준

사용자가 “에이전트 나눠서 해줘”, “병렬로 진행해줘”, “역할 나눠서 구현해줘”라고 명시한 경우에만 sub-agent를 사용한다.

권장 분리:

- Explorer: 기존 PRD/시트/코드 구조 조사
- Worker 1: Apps Script 수집/저장소 계층
- Worker 2: 설문 HTML/응답 UX
- Worker 3: 계산 엔진/룰 처리
- Worker 4: 테스트 케이스/QA Gate

서로 같은 파일을 수정하지 않도록 파일 소유권을 명확히 나눈다.

## 참고 템플릿

- `templates/IMPLEMENTATION_SPEC.md`: 전체 구현 작업 사양서
- `templates/MODULE_SPEC.md`: 모듈별 상세 사양
- `templates/TEST_CASES.md`: 테스트 케이스
- `templates/QA_GATE.md`: 검증 체크리스트

## 참고 스크립트

- `scripts/scan_project.py <PROJECT_DIR>`: 프로젝트 파일 구성과 후보 산출물을 요약한다.
